Lost games, rebuilt and proven.

The one line judges should repeat“The agents rebuilt Doom’s code from the cartridge, and the compiler proved every piece.”

The problem

87% of classic games released in the US are critically endangered (Video Game History Foundation and Software Preservation Network, 2023). For most of them only the compiled cartridge survives. It runs, but nobody can fix it, change it or move it, because the source code is gone.

What we built today

A crew of AI agents that reads a game’s machine code and writes the C source back, one function at a time. A referee compiles every piece with the original compiler and accepts it only if the bytes are identical. Then we splice the agents’ code back into the game and the whole cartridge checksums identical. First patient: GBADoom.

Technical

QuestionAnswerSource
How does matching work? EddyAn agent sees one function’s machine code under an anonymous id and writes C. The referee compiles it with the game’s own compiler and flags and compares the bytes. Identical, it’s a MATCH; one byte off, it isn’t. 0.1 to 0.2 s per check.DECISIONS 11:24
Why byte-identical instead of “behaves the same”?Because it’s a proof, not an opinion. Tests can miss a branch; identical bytes can’t. And identical bytes mean the whole cartridge checksums identical when we put the code back.README
How do you know it isn’t memorized? GBADoom is public.We scrambled our build with small edits and hid the source. From memory alone, Muse compiled 0 of 20. Even with the real headers and compiler errors, 3 of 20 matched, none of them functions we’d changed.DECISIONS 13:28 · lab/out/memory_probe.json
How is the full rebuild proven? EddyObject splice: the referee re-checks every recovered file (each must MATCH), writes the agents’ own compiled bytes into the ROM, and keeps linked addresses only where it proved them identical. 235 agent-written plus 333 original functions: SHA-1 identical, d936259b…, verified on two machines.DECISIONS 11:49, 16:11, 16:12
Couldn’t an agent cheat the compiler, like inline assembly?That’s a fakematch, and we screen for it: the Checker’s rules plus SubQ Snap. 32 fakes rejected, 0 accepted. The final union was re-checked against the fakematch rules with 0 failures.DECISIONS 16:12
Why only 8.39% of the code if you have 41% of the functions?Small functions came first. What’s left is big: the renderer and the status-bar face. That’s 235 of 568 functions but only 11,900 of 141,774 code bytes. The next lever is bigger functions, not more runs.DECISIONS 16:12
What’s hard about the remaining 59%?Size and compiler habits. On big functions one register choice moves every byte after it, so “almost right” is still wrong. Our permuter tried exact rewrites on 17 near-misses at 90% or better and closed none.DECISIONS 15:31 · crew/EXPERIMENTS.md
Which compiler and flags?devkitARM r68, GCC 16.1.0 in Docker, GBADoom’s own Makefile flags minus link-time optimisation, at -O2. Pinned by digest.DECISIONS 11:20 · lab/TOOLCHAIN.md
How would you do another game?Point the same referee at a new target and compiler. We tried Attack on Voxelburg: 4 of 20 on a first run. We don’t claim Doom’s library made it faster: one run each, no measured transfer.DECISIONS 13:43 · lab/TRANSFER.md
Does the recovered code run anywhere else?Six recovered functions compiled for this Mac and for WebAssembly gave the same outputs as the original machine code: 20,000 of 20,000 identical in a browser page. It says nothing about the other 562 functions, and it isn’t a port.lab/demo/equivalence/EQUIVALENCE.md

QuestionAnswerSource
What does “lie” mean?An agent said “it matches” and it didn’t. 39 times today. The referee re-ran each claim and showed the first wrong instruction.tools/counts.py · DECISIONS 16:12
And fakes?Code that passes the byte check by a trick instead of real C. 32 rejected, 0 accepted, across 36 finished runs.same
How do I re-verify a claim myself? EddyAsk in ASI:One. The Excavator agent asks the Referee agent agent-to-agent and only answers with its verdict. Or run python3 tools/counts.py: the tallies come only from files in the repo.DECISIONS 12:46, 15:06
Why trust the referee?It doesn’t think, it compiles. Same input, same bytes, every time, and anyone can re-run it from the repo. Agents lie. Compilers don’t.contracts/

The System That Gets Better

QuestionAnswerSource
Does it get better?Run over run, yes: warm starts and salvage turned near-misses into matches; one 90% near-miss became a MATCH. On held-out code, no measured gain yet: library on versus off, 29 vs 29 of 40 easy, 6 vs 6 of 20 hard. So we don’t claim one.README · crew/EXPERIMENTS.md
Then why build the library?Because the gain we can see is on the hard near-misses, and that’s where the remaining code is. Measuring it honestly on held-out code is the next experiment, not a slide.crew/EXPERIMENTS.md
